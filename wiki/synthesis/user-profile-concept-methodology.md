# 用户画像：概念与方法论（两篇资料综合）

> 综合来源：

> 2. 数猎天下《数据分析之用户画像方法与实践》（datahunter.cn/news/20181212158）— 侧重概念、方法与注意事项
>
> 延伸阅读：[用户画像系列：从标签体系到 AI 检索](topics/user-profile-series.md)（九主题汇编，2026-08-21）

## 一、概念辨析：Persona vs User Profile

两篇文章恰好覆盖用户画像概念的两个层面：

- **User Persona（典型用户/人物角色）**：交互设计之父 Alan Cooper 提出，是从用户群体中抽象出的**典型用户模型**，本质是"描述用户需求的工具"，用于产品设计早期理解用户、想象使用场景——"为所有人做产品"变成"为三四个人做产品"，降低复杂度。**注意：典型用户是虚构的**，不代表真实存在的具体用户。
- **User Profile（数据画像/标签化模型）**：随互联网发展形成的新内涵——根据人口学特征、网络浏览内容、网络社交活动、消费行为等信息抽象出的**标签化用户模型**。核心工作是对海量日志和数据库数据进行分析挖掘，给用户贴"标签"（标签 = 能表示用户某一维度特征的标识）。
- **一句话区分**：Persona 偏调研定性（虚构的典型代表），Profile 偏数据标签（每个真实用户都有对应画像）。

## 二、画像的五个构成要素（永洪版）

用户画像是对现实用户的建模，应包含 5 个方面：

| 要素 | 含义 |
|---|---|
| 目标 | 描述人、认识人、了解人、理解人 |
| 方式 | 非形式化（文字/语言/图像/视频）vs 形式化（数据刻画） |
| 组织 | 结构化 / 非结构化组织形式 |
| 标准 | 常识 → 共识 → 知识体系的渐进过程 |
| 验证 | 画像应来源事实、经得起推理和检验 |

## 三、用户标签的分类（多维度）

- **按变化频率**：静态标签（姓名/性别/出生日期，几乎不变）vs 动态标签（常去的商场、购买品类，按天甚至按小时变动）。
- **按指代与评估**：定性标签（文字描述：爱好"跑步/游泳"）vs 定量标签（数值/数值范围：年龄结构"20-25岁"、单次购买平均金额"300元"）。
- **按来源与生成方式**：基础标签（姓名/性别/年龄等）→ 业务标签（基于业务经验+统计：忠诚度、购买力）→ 智能标签（机器学习自动打标：今日头条推荐引擎）。
- **按体系分层**：一级/二级/三级标签（每层是一个业务维度切面）。
- **按数据处理维度（面向技术）**：事实标签（既定事实直接提取，无需模型）→ 模型标签（对属性/行为抽象聚类，标签=兴趣/偏好/需求，指数=程度/概率）→ 预测标签（ML/DL 预测行为，如试用了 A 预测可能想买 B）。

## 四、标签体系结构与建模

- **标签体系**：叶子标签（能关联到具体用户数据）+ 父标签（对叶子分类汇总），二者相对。设计思路三种：
  - **结构化**：规整树/森林，明确层级父子关系（如性别、年龄人口属性；Yahoo! 受众定向广告平台）。
  - **半结构化**：行业并列 + 业内灵活设计（效果广告，如 Bluekai）。
  - **非结构化**：标签就事论事、无层级（搜索广告关键词、Facebook 兴趣词）。
- **体系层级结构**：原始输入层（清洗）→ 事实层（可验证的准确描述）→ 模型预测层（统计建模/挖掘/ML）→ 营销模型预测层（活跃度/忠诚度/流失度/影响力）→ 业务层（展现层：有车一族、有房一族）。
- **各层建模方法**：
  - 原始数据层：文本挖掘（TF-IDF、Topic Model、LDA）预处理清洗；
  - 事实标签层：分类（预测新用户/信息不全用户）+ 聚类（受众细分/市场细分）+ 相似度计算（余弦夹角、欧式距离）；
  - 模型标签层：回归、决策树、SVM 等，挖掘群体特征与个性权重；
  - 预测层：监督学习、计量回归、线性规划——流失/忠实度/兴趣程度预测。
- **数据建模公式**（datahunter 版）：用户标识 + 时间 + 行为类型 + 接触点（网址+内容）；**标签权重 = 衰减因子 × 行为权重 × 网址子权重**。
- **标签权重细化**（永洪版）：行为类型权重（浏览/搜索/收藏/下单/购买偏序，运营定）× 时间衰减（牛顿冷却定律：t = 初始温度 × exp(-冷却系数 × 间隔时间)）× 用户行为次数 × TF-IDF（tf=标签在该用户出现频率，idf=标签在全体中的稀缺程度）。

## 五、构建流程（方法论）

两篇的构建流程可合并为统一方法：

1. **数据采集**：静态数据（人口属性、商业属性、消费特征、生活形态、CRM 五维）+ 动态数据（行为信息）。定性方法（小组座谈会、深访、日志法、Laddering 阶梯法、透射法）与定量方法（问卷调研+建模）结合补充。
2. **数据清洗**：处理噪声、脏数据。
3. **数据标准化**：最小-最大标准化、Z-score 标准化、小数定标标准化。
4. **目标分析**：明确为每个用户打什么标签、定什么权重（标签=内容表征，权重=可信度/概率）。
5. **数据建模**：事件模型（用户+时间+地点+行为）→ 产出标签与权重。
6. **标签挖掘/生产**：基于规则的标签生产（固定规则 + 数据查询）vs 基于主题模型的标签生产（分类/聚类 + 关键词挖掘偏好）。
7. **数据可视化**：标签数据汇集分析，图表化支撑了解用户与业务决策。

## 六、应用场景

- **精准营销**：智能分组 → 针对群体推送（短信/推送/邮件/活动），点对点交互，高效省钱。
- **用户分析**：用户量扩大后调研失效时的补充手段（新增用户特征、核心用户属性变化）。
- **数据应用/产品**：推荐系统、广告系统（性别/年龄/学历/兴趣/手机等标签投放）、数据产品基础。
- **数据分析**：标签是多维分析天然要素，画像 = 业务层面的数据仓库。
- **产品创新**：基于画像做喜好/功能需求统计，设计符合核心需求的产品。
- **渠道优化**：零售多渠道（门店/经销/电商/APP）按画像匹配产品与渠道。
- **风险控制（金融）**：征信、违约、洗钱、还款能力、保险黑名单等风险画像。
- **数据挖掘**：以画像为基础构建推荐/搜索/广告投放系统。

## 七、体系架构（工程视角）

五层架构：**数据源层**（核心系统 ERP/MES/PLM、CRM、互联网数据、第三方数据）→ **数据采集层**（爬虫/API，结构化+半结构化+非结构化）→ **数据建模层**（产品画像建模：清洗/文本建模/类别识别/品牌识别/属性识别；用户画像建模：清洗/全渠道 ID 识别/信息整合/分析建模）→ **数据应用层**（分析类/服务类/营销类应用、数据 API）→ **行业应用层**。

## 八、三大常见误区

1. **典型用户 ≠ 用户画像**：典型用户是虚构组合（微信白皮书"典型用户的一天"），真实用户各有其画像。
2. **画像 ≠ 标签堆砌**：标签必须与业务/产品结合（海底捞不关心用户"帅不帅、爱不爱玩游戏"）。
3. **要有真正有效的标签**：画像的难点在于建立能提升运营效果的标签——如知识付费"购买课程意愿度"（40% 发券、90% 不发），否则无差别发券徒增成本（电商"大数据杀熟"的本质）。

## 九、关键结论

- 已进入**用户精细化运营**阶段，用户画像标签体系是必备工具；
- 画像内容随行业/产品而异，无统一模板，需紧贴业务场景与业务形态；
- 画像适用于产品全周期：新用户引流、潜在用户挖掘、老用户培养、流失用户回流；
- 画像维度和数据并非越多越好，设计需紧跟业务实际。
