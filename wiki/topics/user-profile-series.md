# 用户画像系列：从标签体系到 AI 检索

## 概述

用户画像（User Profile）是基于用户社会属性、生活习惯、消费行为等数据抽象出的**标签化用户模型**，标签是画像的原子单元。本页汇总用户画像系列文章的参考资料汇编（基础篇 / 提高篇 / 应用篇 共 9 主题），覆盖从标签体系构建到 AI 检索、营销、推荐的完整链路。

**推荐行文主线**：数据（ID-Mapping 统一身份）→ 标签（挖掘/加工）→ 存储（宽表/位图）→ 服务（检索/圈选）→ 应用（营销/推荐/AI）。

## 核心知识点

### 1. 标签体系构建
- **标签三大分类（构建方法维度）**：统计类（性别/年龄/累计消费）、规则类（"近90天交易≥3次=高活跃"，需运营+数据共定）、模型类（机器学习预测：流失概率、商品偏好、价值分层）。
- **标签维度（业务视角）**：基础属性、行为、交易/消费、内容兴趣、社交、设备、生命周期、价值分层。
- **设计要求**：分类明确、结构化（金字塔/树状）、可复用、可扩展；建立**标签字典**（名称、业务含义、计算逻辑、数据来源、更新周期、负责人）。
- **构建流程**：业务目标 → 业务梳理 → 数据收集整合 → 标签分类设计 → 加工实现 → 标签库 → 系统搭建 → 应用维护（关注覆盖率/准确率/更新延迟）。
- **底层依赖**：数仓分层（ODS/DWD/DWS/DM），画像是 DW/DM 层用户数据的二次建模。

### 2. 标签应用场景
- **八大场景**：精准营销与广告投放、个性化推荐、用户运营（促活/流失召回）、产品设计与优化、风险控制（反欺诈）、智能客服/问答、商业洞察与市场细分、内容分发。
- **时效分层**：实时标签（推荐、反欺诈）、准实时（运营触达）、离线（经营分析）。
- **应用闭环**：标签 → 圈选/查询 → 触达/推荐 → 效果回收 → 标签优化。

### 3. 标签挖掘
- **本质**：特征工程 + 机器学习/规则提炼（分类、聚类、关联规则、时序：RFM/LTV/流失预测）。
- **四类产出**：事实标签（直接提取）、统计标签（聚合）、模型标签（聚类/抽象）、预测标签（ML 预测）。
- **典型任务**：用户价值分层（RFM/CLV）、流失预警、性别年龄预测、兴趣偏好、Lookalike 相似人群。
- **工程要点**：样本与标签定义、特征稳定性监控、调度（Airflow）、回填更新策略；质量评估看覆盖率/准确率/时效/稳定性。

### 4. 标签存储
- **分层存储**：Hive（离线结果）、MySQL（元数据/字典）、HBase（实时查询）、ES（海量实时检索+透视）、OLAP 分析型库（CK/Doris/StarRocks/Hologres：宽表+位图）、Redis（在线特征/实时标签缓存）。
- **两种核心模型**：
  - **标签宽表**（一行一用户、一列一标签）：查单用户全量画像，OLAP 列存压缩；
  - **位图 / RoaringBitmap**（一个标签值一张位图，用户 ID 映射位偏移）：按标签找人群，交并差=位运算，秒级圈选。低基数标签高效，高基数/连续值不适合，稀疏场景用 RoaringBitmap 分块压缩。
- **实时/离线双链路**：离线 T+1 批量（Spark/Flink 批），实时（Flink 流 + Kafka）写 Redis/在线库。

### 5. 人群圈选
- **两条路线**：位图路线（位运算，毫秒~秒级，适合亿级）；OLAP 路线（宽表 + SQL，支持复杂条件与透视分析）。
- **高级玩法**：人群包管理（去重/预估/导出）、圈选+透视验证、Lookalike 相似人群扩展、人群包同步投放平台（DSP/短信/Push/企微）。
- **工程要点**：人群预估（不算实际只算量级）、更新策略（一次性/周期性）、版本管理、包大小上限。

### 6. ID-Mapping（OneID）
- **问题**：同一用户多 ID（账号/手机号/邮箱/IMEI/IDFA/OAID/Cookie/微信 UnionID/OpenID），需统一为全局唯一 ID。
- **方法**：规则匹配（标识优先级）、**图计算连通分量**（点=ID，边=关联，同一连通分量=同一用户）、ML 数据融合、优先级取值。
- **典型优先级**：登录账号 > 手机号 > 邮箱 > 微信 UnionID > 设备 ID > Cookie ID。
- **工程要点**：分布式图计算（GraphX/Spark 连通分量）、合并/分裂治理（错误合并难拆）、增量更新、OneID 在线服务化。
- **挑战**：隐私合规（跨域打通敏感）、ID 造假（设备农场）。

### 7. AI 检索：RAG + 两种标签场景
- **RAG 基础**：检索增强生成 = 外部检索 + 大模型生成，解决幻觉/知识过时/私有数据访问；流程：查询 → 检索 → 增强上下文 → 生成。
- **场景一 · 基于标签检索**：标签作**元数据/过滤器**，先按标签缩小范围再语义匹配（"标签过滤 + 向量检索"组合）。例：用户带"金融科技"标签 → 优先检索对应知识文档。
- **场景二 · 基于标签值检索**：标签值（性别=男、等级=白金、情绪=愤怒）作**查询条件**或**注入 Prompt 的个性化上下文**。例：情绪=愤怒 → 转人工/安抚话术。
- **Agent 结合**：动态画像（显式+隐式偏好）、记忆系统（短期对话+长期画像）、LLM 自动打标签（LLM Tagging）反哺画像。

### 8. 基于标签的营销
- **营销闭环**：画像标签 → 圈选人群 → 策略 → 多渠道触达（短信/Push/邮件/企微/广告）→ 效果回收 → 优化。
- **营销自动化（MA）**：行为触发（加购未支付、沉睡唤醒、生日关怀），核心是"对的人 × 对的渠道 × 对的时机 × 对的内容"。
- **DMP vs CDP**：DMP 管匿名 ID（Cookie/设备）人群包同步 DSP/ADX；CDP 管含 PII 的客户档案。
- **效果评估**：触达率/打开率/转化率/ROI + A/B 测试，反哺标签体系迭代。

### 9. 在线推荐
- **架构**：召回 → 粗排 → 精排 → 重排（漏斗），画像贯穿全程。
- **画像角色**：召回（UserCF/双塔向量召回）、排序（长期兴趣画像特征 + 近期行为序列实时特征进 CTR/CVR 模型）、冷启动（基础属性标签 + 热门兜底）。
- **在线 vs 离线**：离线 T+1 画像、在线 Flink 实时标签 + Redis 特征服务；**特征平台**解决训练/在线一致性（Train-Serve Skew）。
- **反馈闭环**：推荐结果 → 用户行为 → 标签更新 → 下一轮更准。

## 合规提醒（应用篇必备）

- 《个人信息保护法》（2021.11.1 施行）：目的明确、最小必要、公开透明、确保安全；敏感个人信息单独同意；自动化决策提供拒绝方式。
- **匿名化（不可逆）vs 去标识化/假名化（可逆）**；K-匿名、差分隐私脱敏。
- 红线：过度采集、跨域数据打通（ID-Mapping 尤其敏感）、广告定向精准识别风险。

## 写作技巧建议

- 每篇一个核心比喻："标签是用户的身份证+体检报告+简历"；"OneID 是把散落各处的用户碎片拼成完整拼图"。
- 配图优先级：标签体系架构图 > 数据流图 > 位图原理图 > 圈选链路图 > 推荐漏斗图。
- 用数据说话：位图 vs 宽表性能对比、圈选秒级响应、推荐 CTR 提升，搜大厂案例数字。
- 系列钩子：基础篇结尾预告"标签怎么算出来、怎么存、怎么查"；提高篇结尾预告"标签最终要变成生意"。
