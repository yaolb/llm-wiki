# PilotDeck 2.0：清华开源的智能体操作系统

> 素材：今日头条「量子位」《清华开源！智能体操作系统任务成本降83%，AI记忆可查可改》（2026-10-17 19:30），原文归档于 `raw/tsinghua-agent-os-memory.md`（9 张图已本地化）。

## 一句话

**PilotDeck 2.0 把「Agent 怎么用」从聊天框升级成操作系统**：以 **WorkSpace（工作舱）** 为基本单位，给每个项目独立的文件系统、记忆库和技能集；再配三根支柱——**白盒记忆**（可查可改可回滚）、**Smart Routing**（强模型决策、弱模型干活）、**Always-on**（离开电脑也继续跑）。由清华 THUNLP 联合面壁智能、OpenBMB、AI9Stars 开源，**AGPL-3.0**。

## 它要解决的四个问题

README 的问题陈述比新闻稿更清楚。从「一次性编程 / 即时问答」转向**长周期、多项目生产力工作**后：

1. 多项目并行时，记忆能否**白盒可追溯**？AI 记错时能否定位到**具体哪条记忆**并直接改，而不是从头开新对话？
2. Token 成本能否**按任务核算**，让后台跑 Agent 在经济上成立？
3. 不同难度的任务能否**自动匹配不同模型**，而不是拿旗舰模型跑鸡毛蒜皮？
4. 人离开键盘后，活能不能继续？Agent 能否**主动发现该做什么**、汇报进展、把成果落地成本地文件？

## 四根支柱

### 1. WorkSpace（工作舱）：项目级物理隔离

每个项目一套**独立文件系统 + 记忆库 + 技能集**。A 舱剪音视频、B 舱写 iOS 小游戏，**记忆和检索空间完全物理隔离**，不串台；检索范围有界；技能随任务自然沉淀。

> 对应的是"**上下文污染**"这个真实痛点：刚让 AI 写严肃架构，转头写小红书文案，它张口还是"架构解耦"。

### 2. 白盒记忆 + Dream 模式

传统 Agent 记忆是**黑盒**：不知道记了什么、何时记的、记在哪；记错关键逻辑只能废掉整段对话重来。

PilotDeck 把**生成 → 抽取 → 存储 → 调用**整条链路对用户可见：

- 面板里**逐条查看**记住了哪些偏好、哪些事实
- **直接改 / 删**，不用写长 Prompt 求它"忘掉"
- **一键固定**重要信息，防止漂移

**Dream 模式**：AI 空闲时在后台对零散交互记忆做**归纳、提炼、去重**；若整理丢细节，**一键回滚**、秒级恢复整理前状态。

### 3. Always-on（常驻执行）

关掉聊天窗口、离开电脑，Agent 仍在后台推进长周期监控与执行：

- 把既定任务跑完
- 执行中**主动发现候选任务**
- 全部完成后**落地为本地文件**，附完整进展与总结报告

### 4. Smart Routing（智能路由）

底层做**任务难度识别**，把任务拆解后分发给不同段位模型，**端云协同 + 分层编排**：

- 复杂规划/决策 → 顶配大模型
- 执行、润色、格式处理 → 降级给轻量模型

## 实测数据（厂商自述）

### ① 自媒体运营场景：约 70% 成本节省

| 配置 | 模型组合 | 成本 | 倍数 |
| --- | --- | --- | --- |
| **Smart Routing 开** | Opus 4.5（主）+ Sonnet 4.5（子） | **$2.83** | **1.1×** |
| Smart Routing 关 | 全部 Opus 4.5 | $12.58 | 5.0× |
| 单体 | 单个 Opus 4.5 长推理（估算） | $12.20 | 4.8× |

### ② 7 个高难复杂任务：约 1/6 成本，效果还更好

任务含播客多语言推送、多源数据报告、领域论文综述、代码库架构文档等。

| 配置 | 得分 | 成本 |
| --- | --- | --- |
| MiniMax-M2.7 单体 | 37.1 | $1.90 |
| Claude Sonnet 4.6 单体 | 69.1 | $18.36 |
| **Sonnet 4.6（主）+ MiniMax-M2.7（子）** | **70.6** | **$3.15** |

→ 相对纯 Sonnet 4.6 单体：得分 **+1.5**，成本 **−82.8%**（这就是标题「降 83%」的出处）。

### ③ Workbuddy Bench

PilotDeck 配 **Qwen3.6-35B-A3B 得 79.1**，**优于 Claude Code 的 77.3**。

## 定位坐标：与同类 Harness 的差别

README 自己画了一张谱系：

- **Claude Code / Cursor / Trae Solo** —— 把模型推理带进**编程 IDE**
- **Claude Cowork** —— 在桌面知识工作里引入**项目级隔离**
- **WorkBuddy** —— 把 Agent 接进企业微信、飞书等 **IM 生态**，一个消息就能唤起

PilotDeck 的站位是**长周期、多项目的生产力工作**，抓手是"工作舱 + 白盒记忆 + 成本路由 + 常驻执行"。原生支持 **MCP**，**Web / CLI / IM（企业微信、飞书）三端行为一致**。

- **源码构建**：面向开发者
- **Docker Compose**：另有容器方式
- 平台：macOS / Linux / Windows

## 值得注意的点

- **「白盒记忆」是这一代 Agent 的真问题**：可查可改可回滚，比"记得更多"更实用——记忆系统的瓶颈往往不是容量，而是**错了没法修**
- **成本路由的判断很朴素但有效**：不是所有步骤都值得旗舰模型；把"决策"和"执行"分开计价
- **Always-on 改变交互范式**：从"你问我答"变成"你交代，它自己推进并交付文件"
- **AGPL-3.0 是硬约束**：想做闭源商业产品要谨慎
- ⚠️ **数据均为厂商自述**：成本、得分、对比基线（尤其 "Claude Code 77.3"）缺独立复现；`Workbuddy Bench` 的评测细节未在新闻稿中展开
