## 一句话

**如果 Jev 证明了"模型可以只输出判断、不输出文字"，Laya 就是把它做成开源可自托管的那一个。**

- **421M 参数**（ModernBERT-large 395M + 决策头）
- **一次前向传播**回答多个带类型的问题
- **三种原语**：`choice` / `score` / `noul`
- 用**严格适当评分规则**做 RL 奖励，**概率真正校准**（不是"看起来自信"）
- **Apache 2.0**、本地可跑、`pip install laya`

> 关系澄清：Laya 作者 **Nandakishor M** 在 2025 年就公开过强化学习决策研究；**TypeSafe AI 随后发布了思路相似的闭源 Jev**；作者再把自己的方案重构成通用 System 1 决策模型，即 Laya。

## 为什么不用 LLM 做反射式决策

每一套现代 AI 流水线的真实瓶颈：**拿生成式大模型去干简单的判断活**。

工单到了、邮件进了、API 来了一条 prompt，其实只需要回答：

- 该给哪个部门？
- 是不是钓鱼邮件？
- 是不是越狱尝试？
- 紧急度 0–3 是哪一级？

为此调 8B / 70B 模型的代价：

| 代价 | 具体 |
| --- | --- |
| 延迟 | 等 **500–2,000 ms**，Token 逐个流式吐 |
| 成本 | 按实际推理付费 |
| 后处理 | 还要写正则 / JSON 解析器从自由文本抠标签 |
| 可靠性 | LLM **爱幻觉**，`confidence: 0.95` 只是"听起来自信的 Token"，**没有任何数学校准** |

> 真正需要的是 System 1：**瞬间反射式判断 + 诚实校准的概率 + 30–40 ms**。

## 三种决策原语

一次并行前向传播完成全部评估，输入是「状态 + 一个或多个带类型的问题」：

| 原语 | 作用 | 返回 | 典型场景 |
| --- | --- | --- | --- |
| `choice` | 从字典定义的候选里选一个 | 选中标签 + 各候选概率 + 置信度 | 部门路由、意图识别、主题分类 |
| `score` | 按有序量表打分（0/1/2/3） | 期望分值 + 各等级概率 + 置信度 | 不满程度、紧急度、危害严重性 |
| `noul` | 回答布尔问题 | 校准后的 **P(true)** ∈ [0,1] | 钓鱼、垃圾邮件、越狱、流失风险 |

> **输出空间被严格限定为概率和数字**——所以模型从不生成文本，**不会幻觉，也不可能输出格式损坏的 JSON**。这是结构性保证，不是提示词约束。

## 架构：4.21 亿参数，两个组件

### 1. ModernBERT-large 主干（3.95 亿）

| 规格 | 数值 |
| --- | --- |
| 层数 | **28** |
| 隐藏维度 | **1024** |
| 注意力头 | **16** |
| GeGLU 中间层 | **2624** |
| 位置编码 | **RoPE** |
| 上下文 | **8,192 Token** |
| 注意力 | **完全双向**（每个 Token 同时看状态与所有选项） |

### 2. [MASK] 选项提取机制

`build_sequence` 把每个选项封装成一个 **`[MASK]` Token**；数据过 ModernBERT + **两层决策头 Transformer** 后，用 `torch.gather` **只抽取这些 MASK 位置的隐藏状态**。

选项评分器 MLP 把每个 1024 维状态投影成**一个标量 Logit**，对该问题所有选项做 Softmax：

```
p_i = softmax(logit_i / T)
```

> **T 是按问题类型和选项数量分别拟合的温度参数**——这是"同一套权重能适配不同选项数"的关键。

### 3. 行动 / 升级处理决策头

真实自动化系统必须判断"何时能信模型、何时交给人"。这个头接收：

- 池化后的 `[CLS]`（1024 维）
- 拼上 **4 个分布特征**：
  - 最高概率 `max(p)`
  - 前两名差值 `p_top1 - p_top2`
  - 归一化熵 `H(p) / log(K)`
  - 选项预算比 `K / 255`

合计 **1028 维** → 两层 MLP → 输出 `[P(act), P(escalate)]`。

### 4. 多问题一次前向

一封邮件 + 5 个问题 → 打包成一个 batch，ModernBERT 在 GPU **一次前向约 35 ms** 处理完全部问题。

## RLCD：让概率真正校准

核心问题：怎么用强化学习训练，还能让概率**不虚高**？

### 两种常见做法都会毁掉校准

| 做法 | 后果 |
| --- | --- |
| **交叉熵**训练分类器 | 只有获胜类 Logit → ∞ 时损失才最小 → 模型**过度自信** |
| **朴素 RL**（对 +1 / 错 0） | 策略梯度把最高概率推向 1.0、其余推向 0.0 → 准确率上去了，**校准被破坏**，变成"自信地犯错" |

### 解法：把严格适当评分规则当奖励

定义：评分规则 `S(q, y)` 是**严格适当**的，当且仅当 `q` 等于真实分布 `p` 时期望得分**唯一最大**。

> 这保证了：**只有报告诚实概率，才能拿到最高奖励。**

复合奖励由三种适当评分组成：

| 评分 | 特点 / 作用 |
| --- | --- |
| **对数评分** `S_log` | 真实结果概率低时**重罚**；为数值稳定，下限截断在 **−9.21** |
| **球面评分** `S_sph` | 取值 **[0,1]** 有界，奖励把概率质量给正确类，**避免对数损失的极端梯度尖峰** |
| **排序概率评分** `S_rps` | 专给有序 `score` 问题；紧急度真是 3 级时，猜 2 比猜 0 好得多——RPS 衡量**累积分布间的平方距离**，教模型理解量表上的距离 |

### 训练细节

- **纯策略梯度（REINFORCE）**，**监督交叉熵损失为零**
- **高斯探索**：每题采样 **G = 8** 组带噪 Logit
- 噪声**投影为零和**（`ε − mean(ε)`）——因为给所有 Logit 加同一常数在 Softmax 中会抵消
- 探索标准差 **σ 从 1.0 衰减到 0.3**
- **组均值优势（GRPO 风格）**：相对 8 个样本的组均值算 advantage

### 成本敏感的行动头 → 自动学到 62.5% 阈值

| 情形 | 奖励 |
| --- | --- |
| 自动行动且**正确** | **+1.0** |
| 自动行动但**错误** | **−3.0** |
| 升级给人工 | **−0.5** |

> 由此推出：自动执行有利的条件是 `P(correct) > 0.625`。**策略自动学会了"置信度高于 62.5% 才动手"**——阈值不是人拍的，是成本矩阵算出来的。

## 多轮轨迹：TD(λ=1.0)

2025 年那版用 PPO 预测销售转化，遇到**数据泄漏**：第 1 轮就喂完整对话嵌入，模型等于"看到未来"。

Laya 的修法：

- 对话按轮切分成**逐步增长的前缀**（第 1 轮 / 前 2 轮 / 前 3 轮…），模型只看截至当前轮的信息
- 用**蒙特卡洛回报**的时序差分，即 **TD(λ=1.0)**
- λ=1.0 时，早期轮次直接对**真实终局结果**训练，而不是从自己的猜测里自举

> 效果：模型能学到"哪些早期对话模式真的会带来转化或流失"。

## 置信度 = 归一化熵

```
confidence = 1 − H(p) / log(K)
```

- 完全不确定（所有选项都是 1/K）→ H = log(K) → **置信度 0.00**
- 完全确定（某选项 1.0）→ H = 0 → **置信度 1.00**

> 这是**分布形态**算出来的，不是模型"说"的。所以可以直接写进业务判断。

## 数据：不用任何合成标签

文中明确反对用 LLM 生成合成训练数据与标签：

> **用合成标签训练校准模型，只会让模型对齐到大模型自己的错误和幻觉。**

训练用 **100% 人类标注的真实公开数据集**，覆盖：客服分流与意图、推断与事实核查、内容安全（毒性/骚扰）、安全护栏（真实越狱与注入攻击）、量表评分（帮助性/复杂度/正确性）、多轮轨迹（有已验证终局的 SaaS 销售与客服）。

**防走捷径**：动态打乱选项顺序、改写问题表述、在原始文本与嵌套 JSON 状态间交替、注入随机干扰问题。

## 怎么跑

```bash
pip install laya
modelscope download --model convaiinnovations/laya --local_dir convaiinnovations/laya
```

```python
import laya
agent = laya.load("convaiinnovations/laya")

state = {
    "from": "user@company.com",
    "subject": "Charged twice on March invoice",
    "body": "Hi, we were billed twice for invoice 4411. Please refund the duplicate today or we will cancel our plan."
}

questions = {
    "department": {"type": "choice", "instructions": "Which department should handle this email?",
                   "criteria": {"billing": "invoices, payments, refunds",
                                "technical": "bugs, outages, system errors",
                                "sales": "pricing, new contracts",
                                "other": "everything else"}},
    "urgency":    {"type": "score", "instructions": "How urgent is this request?",
                   "criteria": ["not urgent", "soon", "critical deadline or blocking issue"]},
    "churn_risk": {"type": "noul", "instructions": "Does the user threaten to cancel or leave?"},
    "is_phishing": {"type": "noul", "instructions": "Is this email a phishing or scam attempt?"},
}

result = agent.predict(state, questions)
answers = result["answers"]
# department -> billing (0.94) / urgency -> 1.84 / churn_risk -> 0.892 / is_phishing -> 0.008
```

**门控逻辑**（因为概率校准过，路由可以写得极简）：

```python
dept = answers["department"]["choice"]
conf = answers["department"]["confidence"]
if conf >= 0.85:
    route_automatically(dept)
else:
    send_to_human_triage(dept, reason=f"Low confidence ({conf:.2f})")
```

## 待验证 / 证据边界

- **全文为项目方自述**（ModelScope 社区推广文），**无第三方独立复现**；HuggingFace 热门榜第三、2.1k Stars 是**发布当时**的说法，目前仓库已 ⭐33,414
- **"比 Jev 快 4 倍"是拿 Jev 的"最佳 150 ms"比的**；对 Jev 平均 400 ms 其实是 10.4 倍。**两者硬件、任务集、批处理方式均不同**，不是同条件实测。Jev 是云端 API（含网络往返），Laya 是本地 GPU 前向——**比较口径不对等**
- **"自托管成本 $0.00"忽略 GPU 摊销与电费**，只在"已有闲置算力"时近似成立
- **零样本 ECE 0.207、情感评分 36.2%** 说明校准是**任务家族内**性质；跨域使用必须先自测 ECE
- 数据集"100% 人类标注公开数据集"为**自述**，未见数据卡与标注一致性报告
- "2,400 个零样本问题"的**任务家族划分方式未公开**，无法判断零样本难度是否被低估或高估
- 62.5% 自动行动阈值由成本矩阵 (+1 / −3 / −0.5) 推出，**换成本结构阈值就要重算**
- 模型 0.4.11 版本迭代快（9-18 建仓，10-17 仍在推送），**API 不稳定**；仓库描述提到的 100+ 语言与 router 在正文中未展开
- 任务内准确率 83.8% 是**宏平均**，被 58.1%（回复质量）和 62.8%（搜索相关）两项拉低——**不要当成所有任务都能到 90%+**
