# IDMapping — 58 用户 ID 关系映射体系

## 概述

IDMapping 是 58 同城大数据部的用户身份映射服务，位于 **03-数据应用部** 下。其核心职责是在 58 体系内的多种用户标识体系之间建立准确的对应关系，使不同业务线的数据能够以统一的用户视角进行关联分析。

## 背景

58 同城旗下有 58 同城主站、安居客、转转等多个品牌及业务线，各业务线使用不同的用户 ID 体系：

- **imei / wimei**：设备维度标识
- **wuser**：用户维度的统一标识
- **58-id / anjuke-id**：各品牌自有用户 ID

当需要跨业务线进行数据分析、标签计算、定向投放时，必须在这些 ID 之间建立映射关系。

## 发展历程

根据美事文档的目录结构，IDMapping 经历了以下版本演进：

1. **idmapping 1.0** — 初始版本，建立基础的 ID 映射能力
2. **idmapping 2.X** — 版本迭代，扩充映射覆盖范围
3. **idmapping 3.X** — 当前主力版本，完善映射能力和数据质量
4. **SmartIDMapping 下线** — 下线了 SmartIDMapping 方案（替代方案见腾讯文档）
5. **实时 IDMapping** — 实时场景下的 ID 映射能力
6. **图腾项目** — 与 IDMapping 相关的项目（具体关联方向待补充）

## 技术方案

### 实时 IDMapping（V1.0）

由陈丽媛（2022-09-30）设计，主要面向万象平台的实时场景。

**触发场景：**
- 万象平台实时事件触发下的自动化短信营销（面向 58 同城和安居客两个品牌）
- 第一批 wimei 账号的实时标签应用于用户的实时个性化资源位投放
- 招聘业务接入的实时标签为 wuser 体系，原有用价无法使用

**覆盖能力：**
1. **实时标签 ID mapping** — 将设备级标识（wimei）映射为用户级标识（wuser），使实时标签计算能够覆盖招聘等业务
2. **实时事件 ID mapping** — 将不同体系的用户事件关联，实现跨业务的实时事件分析

## 应用场景

- **万象平台**：实时标签计算、AI 圈人、人群包生成中的 ID 统一——是 [[user-code-encoding]]（位图 bit 索引）的输入上游，ID 映射结果经编码后进入 [[user-tag-bitmap-construction]] 位图构建
- **实时营销**：自动化短信、App 推送等场景中的用户识别
- **跨品牌分析**：58 同城与安居客等品牌的用户数据打通
- **投放定向**：个性化资源位投放的用户定向
