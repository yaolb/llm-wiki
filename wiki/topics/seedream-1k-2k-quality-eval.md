# Seedream 5.0 Pro 清晰度差异与 1.5K 图生图质量评测

> 素材：ChatGPT 会话《解释清晰度差异》（用户自有账号，2026-10-19 经 ego lite 提取），原文归档于 `raw/chatgpt-seedream-1k-2k-quality-eval.md`。
> **来源性质**：ChatGPT 生成的分析与评测方案，非正式出版物；分辨率档位、价格与 API 参数需以火山方舟官方文档为准。

## 一句话

**1K 与 2K 的效果差距，远大于像素量差距**——不只是分辨率，还涉及生成空间、细节表达能力、生成策略与随机性。而在电商换装场景，**1.5K 是个被忽略的甜点位：与 1K 同价，效果更优**。

## 官方档位（对话中的转述）

| 参数 | 1K | 1.5K | 2K |
| --- | --- | --- | --- |
| 正方形尺寸 | 1024×1024 | 1536×1536 | 2048×2048 |
| 像素量 | 105 万 | 236 万 | 419 万 |
| 相对 1K 像素量 | 1 倍 | 2.25 倍 | 4 倍 |
| 官方质量说明 | 基础 | 优于 1K | 更高分辨率 |
| 价格 | 相同 | **与 1K 相同** | 另行计费 |

> ⚠️ 对话称"官方确认 1.5K 与 1K 同价且效果更优"，**建议回火山方舟文档核对**，价格与档位可能变化。

## 为什么差距可能远大于像素差距

| 可能原因 | 技术解释 | 典型现象 |
| --- | --- | --- |
| 生成空间不同 | 分辨率影响模型处理的空间信息规模 | 构图、结构变化 |
| 细节表达能力 | 1K 难以充分表达细小纹理与复杂结构 | 裤缝、拉链、手指失真 |
| 生成过程差异 | 不同档位可能采用不同计算/解码策略（内部未公开） | 不只是清晰度变化 |
| 随机生成差异 | 两次请求本身就可能不同 | 相同参数也有差异 |
| 参考图信息利用 | 输出分辨率影响细节重建与参考特征表现 | 商品颜色、版型不一致 |

> ⚠️ **不能直接认定** 1K/2K 用了不同模型、不同推理步数，或 2K 一定做了二阶段超分——官方资料未披露。

## 电商换装最该关注的三个问题

1. **颜色还原**：分辨率本身不决定颜色准确度。1K 与 2K 主色差异大，说明不是同一张图的缩放。用 OpenCV 在**相同裤子有效面料区域**算 **Lab ΔE00**，排除背景/皮肤/阴影。
2. **结构保持**：1K 常改口袋/裤脚/手部姿势，可能是低分辨率细节表达不足；但 2K 若更容易改结构，要查参考图、提示词和随机性，**不能简单归因于清晰度**。
3. **是否值得直接上 2K**：做受控实验，固定模型版本、输入、提示词、宽高比、格式，每档独立生成 ≥10 张，比较**统计分布**而非单张。

## 六维质量评测体系

| 维度 | 权重 | 评测方法 |
| --- | --- | --- |
| 非编辑区域保持度 | 25% | OpenCV + SSIM |
| 商品特征一致性 | 25% | 视觉模型 + 局部特征 |
| 视觉自然度 | 20% | 视觉模型评审 |
| 色彩一致性 | 15% | OpenCV Lab + ΔE00 |
| 清晰度与细节 | 10% | Laplacian + 边缘特征 |
| 生成缺陷检测 | 5% | 视觉模型 + 图像规则 |

```
Q = 0.25P + 0.25F + 0.20N + 0.15C + 0.10D + 0.05A
```

各子项标准化到 0–100；权重是建议初值，**需用人工标注样本校准**。

**硬性验收条件**（独立于综合分）：手部缺失、裤子结构明显错误、保护区大面积修改——即使综合分高，也直接判不合格。

> 为什么不只用 PSNR/SSIM：图生图是**生成式编辑**，裤子本来就要变，像素差异大不代表质量差。

## Java + OpenCV 实现要点

四个确定性指标：

1. **保护区 MAE**：`Core.absdiff` + `Core.mean(diff, mask)`
2. **保护区 PSNR**：MSE → `10*log10(255²/mse)`
3. **局部 Laplacian 清晰度**：灰度 → `Imgproc.Laplacian` → `Core.meanStdDev` → 方差
4. **商品图与生成图 Lab 平均色距 ΔE76**：转 float RGB → Lab → 按 Mask 取均值 → 欧氏距离

> ⚠️ 示例用 **ΔE76**（基础色差），生产建议升级为 **CIEDE2000（ΔE00）**。

### 三个实施前提

1. **保护区蒙版与源图、结果图尺寸必须一致，且已完成空间配准**——不能靠强行缩放掩盖构图偏移
2. 商品图与生成图不必同尺寸，但各自蒙版要匹配对应图片，并**排除强阴影、高光、非面料区域**
3. **Laplacian 方差不能直接当质量分**：噪点、过度锐化也会让它升高，需与噪声检测、视觉评审结合

## 视觉模型评审（补 OpenCV 的短板）

OpenCV 无法可靠判断手指畸形、裤子缺口袋、褶皱是否符合人体结构——需独立视觉模型输出结构化 JSON：

```json
{
  "task": "evaluate_image_edit",
  "dimensions": {
    "naturalness": {"score": 0, "issues": []},
    "product_fidelity": {"score": 0, "issues": []},
    "anatomy_consistency": {"score": 0, "issues": []},
    "artifact_detection": {"score": 0, "issues": []}
  },
  "critical_defects": [],
  "reason": ""
}
```

输入：原始模特图 + 商品图 + 生成图 + 必要局部裁剪。要求按固定标准打分并指出可观察缺陷，**避免凭主观审美给分**。

## 建议验收阈值（初始试运行值）

| 指标 | 建议目标 | 作用 |
| --- | --- | --- |
| 综合质量得分 | ≥85 | 总体质量 |
| 保护区 PSNR | ≥35 dB | 非编辑区域检查 |
| 保护区 MAE | ≤3/255 | 背景/人物变化 |
| 商品色差 ΔE00 | ≤5 | 颜色还原 |
| 视觉自然度 | ≥85/100 | 真实感 |
| 重大结构缺陷 | 0 个 | 硬性条件 |
| 图片尺寸 | 符合 1.5K 档位预期 | 参数验证 |

> 这些是**建议值，不是 Seedream 官方标准**；需用人工标注合格样本校准。色差应优先用 CIEDE2000，并对**多个有效面料区域分别计算**，不要只比全局平均色。

## 实验设计

- 准备 **100 组**电商换装样本，每组相同参数生成 **5 次**，共 **500 张**
- 同批样本分别跑 1K / 1.5K / 2K，**盲评**
- 比较：综合得分、严重缺陷率、生成时延、**每张合格图成本**

```
每张合格图成本 = 全部生成及评测成本 / 最终合格图片数量
```

> 比单次 API 价格更能反映真实业务价值。

## 落地建议（两阶段）

1. **纯 Java + OpenCV 自动评测**：保护区 MAE/PSNR、颜色偏差、清晰度、分辨率检查，先建稳定批量流水线
2. **增加视觉模型**：识别服装结构、人体异常、生成伪影、整体自然度，用人工标注校准权重与阈值

> 建议做成**独立 Java 质量评测服务**，Seedream 生成完自动调用，返回评分、缺陷信息和"是否重生成"的决策；换模型也能沿用同一套标准。
