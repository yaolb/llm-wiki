# 12 个设计 Skill：从设计系统到视觉验收

## 来源与核心判断

- **文章**：[AI做UI丑？这12个设计Skill，让它秒变设计总监！](https://mp.weixin.qq.com/s/TRbpBbr2QTG8tDvu-1DhuQ)，布焦绿的人生指南，2026-10-31。
- **性质**：个人推荐和使用体验；“必装”“设计总监”是作者评价，不是标准化评测结果。
- **原文**：`raw/ui-design-twelve-skills.md`；本地 HTML 快照位于 `raw/assets/ui-design-twelve-skills/original.html`，正文无图。作者称地址放在图中，但抓取正文未见图片，以下仓库匹配是补充核对而非原文链接抄录。

## 摘要

文章把 AI 界面的模板化归因于缺少设计判断，提出用专业规则约束字体、颜色、间距、布局和动效。它分三档推荐：基础档为 ui-ux-pro-max、taste-skill、huashu-design；进阶档为 MengTo Skills、scroll-world、emilkowalski/skills；按需档为 make-interfaces-feel-better、designer-skills、UI Skills、Design OS；再补充 awesome-design-skills 与 Anthropic Frontend Design，共 12 项。

核心建议是少量组合而非全量叠加：用一个设计系统类技能打底，再用审美判断类纠偏。作者还称可把说明文件发给豆包等对话助手参考，但这只能说明规则文本可被阅读，并不等于相应脚本、素材、浏览器检查和工具链都能运行。对已有项目，保留产品身份、先定方向、实现后检查真实页面，比单纯累加 Skill 更值得沉淀为工作流。

## 对原文的关键补充

1. **星数不是效果验证**：文章日期与当前快照不同。尤其 emilkowalski/skills 原文 2.6k、核对 57,350，相差很大；目前不能确定是历史快照、统计时点不同还是原文数据有误。
2. **不是 12 个相同形态的插件**：MengTo、Emil、designer-skills 是集合；Design OS 是产品规划与设计交接工具；Frontend Design 是官方仓库内一个子目录，不能把整个仓库的星数当子技能热度。
3. **awesome-design-skills 不只是工具排行榜**：官方 README 定位为 67 种设计系统风格注册表，每种包含 SKILL.md 和 DESIGN.md；适合选风格，不等于安装一个“万能设计师”。
4. **“喂文档”不等于完整安装**：UI UX Pro Max 包含 Python 检索/设计系统工具；Taste Skill 包含素材、脚本及实际浏览器检查；scroll-world 的官方流程依赖图像/视频生成服务，存在外部服务和生成成本。单发 SKILL.md 只能迁移部分规则，不能等价复现执行链。
5. **产品界面与宣传落地页分开选**：scroll-world 主要做连续镜头的滚动叙事页面，不宜直接视为数据后台或业务表单的通用解决方案。

## 可复用工作流（本页综合判断，未实测）

- 输入产品目标、真实内容、现有设计规范和参考；先约定受众、视觉方向与约束。
- 一个主技能负责设计系统或完整流程；动效、无障碍、审美纠偏按任务加载，避免同时激活互相冲突的主流程。
- 在真实浏览器检查响应式、长文本、键盘焦点、交互状态与动效；以页面行为和截图验收，不以“已安装 Skill”验收。
