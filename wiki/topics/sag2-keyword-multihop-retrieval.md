# SAG2：不建向量库、不调模型建库的本地知识库

## 一句话

**建库阶段一个模型都不调、不做 embedding、不要向量数据库——用 90 年代的 BM25 做粗筛，再用 Jev 判断证据，多跳线索靠关键词在原文里现找。**

## 核心数字（作者实测 / 项目方自报）

| 项目 | 数字 |
| --- | --- |
| 建库耗时 | **11,656 段：4.57 小时 → 2.36 秒**（约 7,000 倍） |
| 建库 Token | **2,826 万 → 0** |

## 机制：把 RAG 的路反过来走

### 传统路线的演进逻辑

- **RAG（2020 起）**：切块 → 向量化 → 相似度召回；成熟，但**多跳弱**（文档 3 里可能一个关键词都不重合）
- **GraphRAG / LightRAG / HippoRAG 2**：入库前用大模型抽实体关系建图；多跳强了，但**贵且重**
- **LLM Wiki 思路**：让模型把资料编译成 wiki 页面；对个人友好，但**逐篇读写成本高、原文一改就要重写**
- **NotebookLM**：云端、来源有上限、本地 Agent 不好调用

> 规律：**每往前走一步，都是在入库时多花一点钱、多调一点模型，换检索准确度。**

### SAG2 的做法

```
BM25 粗筛候选段落
  → Jev 判断「这段是不是有用证据」
  → 从被判定有用的段落里抽关键词
  → 用新关键词继续搜
  → Jev 结合已有证据再判断新命中的内容
  → 直到线索闭合或达到轮次上限
```

- **索引**：直接对原文建**关键词倒排索引**，BM25 打分（Elasticsearch 默认打分也是它）
- **语义判断**：交给 **Jev**——不生成文字，只回一个判断与分数，**又快又便宜**
- **多跳桥接**：一个关键词连多个段落，一个段落含多个关键词，**这些联系直接来自原文，无需预处理**

### 与 SAG 一代的区别

| | SAG 一代 | SAG2 |
| --- | --- | --- |
| 建库 | 调大模型逐段抽「事项 + 实体」 | **不调模型**，纯 BM25 索引 |
| 串线索 | 用 SQL 把事项实体串起来 | 关键词在原文里**现找现连** |
| 建库成本 | 4.57 小时 / 2,826 万 tokens | **2.36 秒 / 0 token** |

## SAG Wiki：能直接用的桌面端

- 仓库：`Zleap-AI/SAG-Wiki`，**Rust**，**MIT**，⭐157
- 体积：Windows 约 **13 MB**，macOS 约 **18 MB**
- 用法：**添加一个本地文件夹就是知识库**；文件不用动，改了**自动增量更新**
- 配置两步：**问答模型**（自选，如 DeepSeek V4.1 Flash）+ **决策模型**（官方固定 Jev，填 Key 即可，也可改别的）
- 支持格式：常见文档之外，**音频、视频**也能索引（设置 → 文件设置 → 其他格式）

## 作者的四组实测

**① 383 篇公众号文章**
- 问「蒸馏文章一共处理了多少篇、多少字」→ 两次检索命中，答出 **138 篇、79 万字**
- 追问「把视频/多模态工具接进 Agent 的实测」→ 跨文章挑出 LibTV、拓、Remotion 等案例，排成表格并带引用

**② 10 万条维基词条（全机索引 100,461 个文件）**
- 任务：用几步把「李白」和「爱因斯坦」连起来，每步必须有出处
- 原生 DeepSeek：靠刘慈欣作品《朝闻道》《诗云》同框
- **SAG2**：关键词定位到学者**林庚**——他年轻时在清华物理系痴迷相对论，后写《诗人李白》→ **从相对论连到李白，全程有原文可查**

**③ 26 份半导体研报（几十万字）**
- 问题：谁独家供应 SK 海力士的底层填充胶（Underfill）？
- **SAG2：3 次工具调用**命中 Namics 的供货原句
- 原生：**11 次调用**才勉强命中

**④ 代码排错（SAG Wiki v0.2.6 源码）**
- 问题：Jev 遇网络错误时的重试逻辑
- **SAG2**：直接给出文件、行号、关键代码——命中「HTTP 499 重试时不增加失败计数」
- 总耗时：**144 秒 → 95 秒**

## 判断：它到底新在哪

**① 把「预处理成本」推迟到查询时**
不建图、不做向量、不抽实体——**索引只做倒排**，语义判断放到检索过程中。这是对「入库时多花钱换准确率」这条主线的反向操作。

**② 用判别模型替代嵌入模型**
Jev 只输出「有用/无用 + 分数」，比 embedding + rerank 更便宜，也比让 LLM 读全文更省 Token。

**③ 增量更新天然友好**
文件改了只要重建倒排局部，**不需要重算向量、不需要重跑抽取**。这是它相对 GraphRAG 的实用优势。

## 局限（需要冷静看）

- **多跳依赖「关键词桥接」**：如果两段之间没有任何词面重合（同义改写、跨语言、代词指代），BM25 就断了；作者的两个成功案例都存在**显式关键词线索**
- **语义泛化弱于向量检索**：问法与原文措辞差异大时，召回会掉
- **强依赖 Jev**：官方配置固定 Jev，换别的决策模型效果未公开
- **评测多为自报**：8 项第一、7,000 倍加速均来自项目方与作者，**无第三方复现**
- **EnterpriseRAG-Bench 是「模拟」企业数据**，不是真实企业库
- SAG-Wiki 仅 ⭐157、2026-10-18 建仓，**工程成熟度未知**

## 与库内线索的关系

- [[Jev 模型：单步判别式决策模型]] —— **SAG2 是 Jev 的一个真实生产用例**：把「判断这段有没有用」这件事交给判别模型，而不是让 LLM 读全文。两者的成本结构正好互补（BM25 零成本粗筛 + Jev 极廉价精判）
