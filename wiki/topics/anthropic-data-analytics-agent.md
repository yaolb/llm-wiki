# Anthropic 数据分析 Agent：Claude 自动化 95% 内部数据分析

## 概述

Anthropic 官方博客分享数据团队实践：用 Claude 自动化 **95% 的商业分析查询**，整体准确率约 **95%**，把数据科学团队解放出来做因果建模、预测和机器学习。文章完整拆解了分析 Agent 的三类失败模式、分层技术栈（数据基础/可信数据源/Skill）和三级验证体系（离线评测/消融实验/在线验证），并公开了数据仓库 Skill 的完整框架。

## 核心观点

1. **数据分析不是写代码**：写代码是开放解题空间、创造性加分；分析查询只有一个正确答案、来自一个正确数据源，无法确定性验证——复杂性来自数据本身的模糊性，核心是把用户问题准确映射到数据模型的具体字段。

2. **三类失败模式**：① 概念与字段映射模糊（几百到数百万候选字段）② 数据过期（业务定义/表结构变化）③ 检索失败（搜索空间太大找不到正确信息）。

3. **分层技术栈各治一病**：数据基础（权威数据集 + 三重执行标准 + 单一代码库 + 元数据一等公民）治映射模糊；可信数据源（语义层 > 数据血缘 > 查询语料库 > 业务上下文）治映射模糊；Skill（程序性知识）治检索失败。

4. **可信数据源的四个层级**（按可信度排序）：语义层（编译好的指标定义，强制优先使用）→ 数据血缘/转换依赖图 → 查询语料库 → 业务上下文（公司知识图谱，大多数团队跳过、Anthropic 也低估最久的一层）。

5. **查询语料库的教训**：直接给 Agent 访问数千个历史 SQL，准确率变化不到 1%——非结构化检索无法把新问题映射到正确历史案例；要提炼成结构化的、按领域划分的参考文档和可复用分析模式写进 Skill。

6. **Skill 是关键杠杆**：不加 Skill 评测准确率不超过 21%，加了之后稳定 95%+（某些领域约 99%）。成对创建：知识型路由器 Skill（顶层轻量路由，范围收窄到几十个整理过的文件）+ 行动手册型 Skill（Unbook，编码资深分析师流程 + 十几个可复用分析模式）。

7. **Skill 维护是工程任务**：Markdown 与转换模型同一代码库，改模型 PR = 更新文档 PR，CI 钩子强制（约 90% 数据模型 PR 含 Skill 变更）；不维护的代价——上线 95% 准确率一个月后跌到 65%。

8. **验证三件套**：离线评测（看板+长尾、固定基准值防漂移、评测结果存数仓、按领域 90% 上线门槛）→ 消融实验（每次只改一个变量、负面结果也是结论、PR 粒度对比）→ 在线验证（对抗性审查 +6% 准确率但 +32% token/+72% 延迟、来源页脚、数据质量检查、被动监控、主动收集纠正案例）。

9. **静默失败未解决**：答案错了但看起来合理、无人质疑直接用——目前只有缓解手段（来源页脚、高层内容人工确认、核心 KPI 每日与权威看板对比），没有完善方案。

10. **从零开始**：几个权威数据集 + 几十个离线评测 + 一个轻量知识型 Skill 就能拿到大部分收益；先对齐五个问题（现在 vs 未来准确性、业务复杂度、受众技术水平、成本意愿、权限/隐私底线）。

## 关键数据

- 95% 分析查询自动化 / 约 95% 整体准确率
- 无 Skill：评测集准确率 ≤21%；有 Skill：95%+，部分领域约 99%
- 对抗性审查：准确率 +6%，token +32%，延迟 +72%
- 查询语料库直接访问：准确率变化 <1%（答错问题约 80% 答案其实在语料库里）
- Skill 不维护一个月：95% → 65%
- 约 90% 数据模型 PR 与 Skill 变更同 diff
- 评测数量：每主题超过几十个用例后边际收益递减
