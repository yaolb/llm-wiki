# OpenAI 内部数据代理（Data Agent）

## 一句话定义

OpenAI 数据平台团队用 2 名工程师、3 个月构建的内部数据代理（Data Agent），核心理念是「vanilla agent, rich foundation（朴素的代理，丰富的基础设施）」：代理本身保持极简，全部工程投入用于构建统一、整洁、健壮的数据地基与上下文层。

## 背景与瓶颈

- 数据平台存储 **1.5 exabytes** 数据，横跨 **90,000 张表**，服务约 **4,000** 名内部用户
- 核心洞察（Emma Tang）：数据分析最难的不是写 SQL，而是**找到正确的表、正确理解表语义**。许多表看似相似但含义完全不同（粒度、关联、是否含已登出用户等）
- 70% 的代码由 AI 编写；验证了「2 名工程师 + 3 个月」即可交付

## 接入点（嵌入工作流）

代理在所有员工已工作的场景中无缝嵌入：
- Slack 机器人
- Web 门户
- IDE 集成
- Codex CLI（MCP 协议）
- 内部 ChatGPT（MCP 连接器）

## 四大组件架构

1. **单一 LLM**：每个请求都用 GPT-5.5 作为基础模型。无路由器、无多模型混合、无微调
2. **Runtime（运行时）**：编排器，解析模型输出 → 调度工具调用 → 反馈结果，形成「推理→行动→观察→再推理」循环
3. **Context Assembly（上下文组装）**：真正的工程核心。没有正确的上下文，再强的模型也会答错；裸 schema 不足以区分表
4. **工具集（仅 13 个）**：涵盖公司上下文查询、内部知识库、Airflow/Spark 等大数据系统、元数据服务

## 六层上下文（让一个模型搞定 90,000 张表）

| 层 | 内容 | 说明 |
|----|------|------|
| 1 表使用元数据 | schema、血缘、历史查询 | 高频仪表盘查询（数据科学家编写、正确可复用）权重最高，一次性探索查询最低 |
| 2 人工注释 | 表所有者描述 | 业务含义、所有权、关键性、注意事项（无法从 schema/查询推断） |
| 3 Codex 代码富化 | 秘密武器 | 每晚爬取每张表的管道代码，每批 100-200 张、每张 5-10 分钟，捕获实际数据内容、派生方式、新鲜度、何时用而非相似表 |
| 4 制度知识 | Slack/Google 文档/Notion | 单独提取嵌入，经访问控制检索服务提供，避免越权暴露 |
| 5 记忆 | 之前对话的修正与学习 | 分全局级与个人级 |
| 6 运行时上下文 | 直接查数仓/Airflow/Spark | 离线上下文缺失或过期时实时填补 |

**离线索引**：前 3 层（表使用元数据、人工注释、Codex 富化）由每日管道合并成每张表的单一描述 → 嵌入成向量库。**运行时**检索最匹配的表描述，记忆层叠加修正。

## 从问题到验证答案：三步走

1. **向量化问题**：用与离线相同的嵌入模型转换用户问题
2. **组装上下文**：向量库语义搜索 + 精确文本匹配，经访问控制检索制度知识，添加相关记忆
3. **启动代理循环**：上下文发给 LLM → 写 SQL → 看结果 → 再试直到正确

可靠性来自「问题被提出之前就已准备好的六层数据基础设施」。

## Codex 三大实战案例

1. **跨云迁移 2 个月完成**：10,000 DAG / 90,000 表 / 600 PB。难点在依赖图（表构成 DAG，无法随意排序）。Codex 生成数十万 PR 指向新云。同类迁移其他公司通常要数年
2. **无人参与的开源补丁发布**：运行在十几个开源工具（Spark/Kafka/Flink）上，Codex 驱动发布代理验证补丁→诊断→建议修复→发布→告警，已连续 3-4 个月零人工、零事故
3. **智能工单闭环**：支持机器人处理常见问题，难解决的交给 Codex 调查/修复，工程师审查批准。工程师从每小时级处理提升到每天约 100 个修复

## 五条经验教训

1. **先打好数据地基**：代码代理的真相是仓库，数据代理的真相是整个公司。数据分散就先投资基础设施，而非代理
2. **工具贵精不贵多**：最初接 40 个工具结果很差（模型选错工具、被重叠工具的冲突答案搞混）；收敛到 13 个并去掉重叠工具后解决
3. **不是所有查询都值得学习**：按可信度排名，高频仪表盘查询最高，一次性探索查询最低
4. **指令越少越好**：详细逐步指令反而损害结果；高层指导 + 正确上下文与工具 + 信任推理能力更有效
5. **重新定义时间线**：项目听起来该花一年，就问「用 AI 代理能不能一个季度完成」

## 未来方向

- **按需生成应用**：已能按需构建传统仪表盘；下一步生成定制 React 应用连接后端，数秒构建、跑在真实数据上
- **平台侧代理**：下一个挑战不是面向用户的代理，而是面向平台侧的代理——分流进来的代码、运行前验证、吸收 AI 增强用户带来的代码洪流。用户可能「vibe-code」出自己不懂底层机制的代码（如"我不知道 Flink 怎么工作"）

## 结语金句

> "A coding agent has one source of truth: the repository. A data agent's source of truth is the whole company."
> — Emma Tang, Head of Data Platform Engineering at OpenAI

GPT-5.5 在 API 上可用、Codex 公开、MCP 是开放协议——所有工具任何认真团队都能拿到。区别在于统一整洁的数据基础 + 精心设计的上下文层 + 让代理保持简单的意愿。
