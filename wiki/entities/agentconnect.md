# AgentConnect

## 概述

AgentConnect 是一个**开源、可自托管的 Agent 托管平台**，把 Anthropic「Claude Tag」所代表的 **@Agent 下发任务**模式做成了可自行部署的产品：在 Discord / Slack / Telegram 等 IM 频道里 @某个 Agent 角色，任务进入后台执行，完成后回传结果。

作者（微信公众号「AI产品银海」）的定位一句话：**"任务下发、后台执行和结果回传都由同一套平台承接。"**

## 核心信息

- **全称**：AgentConnect
- **类型**：工具（开源 Agent 托管平台）
- **协议**：Apache 2.0
- **部署**：自托管；企业可把运行环境、凭证和业务数据留在自己控制范围内
- **仓库**：https://github.com/agentconnect-md/agentconnect
- **可更换的三层**：模型 / Agentic 框架（Harness） / 消息渠道
- **消息渠道**：Discord（文章演示用）、Slack、Telegram、GitHub、GitLab
- **触发方式**：IM @ 调用、Webhook、代码仓库事件、定时计划（Schedule）

## 能力拆解

### 1. 多 Agent 角色托管

每个角色是一套独立配置，**互不干扰**：

| 配置项 | 说明 |
|--------|------|
| 模型 | 每个角色单独选择 |
| 记忆 | 角色级 |
| 工作区（Working Directory） | 角色级 |
| 权限 | 角色级，可单独设置 |
| MCP | 角色级，可加自定义 MCP 服务 |
| Connectors | 角色级 |
| Skill | 角色级 |
| 沙箱服务 | 角色级 |
| 执行框架（Harness） | **一键创建**：Claude Code / Codex / DeepSeek Harness 等 |

举例的角色划分：**选品 Agent**（商品分析）、**金融 Agent**（市场数据）、**内容 Agent**（生成物料）、**海报 Agent**（品牌 Skill + 图像模型）、**影视 Agent**（分镜 Skill + 视频模型）。

> 关键差异点：**Harness 可换**——不绑定某一家 Agent 框架，这是它与 Claude Tag（绑定 Claude）最大的不同。

### 2. 任务的完整链路

```
IM 里一次 @  →  任务接收  →  找到对应 Agent 角色  →  Agent 执行（调 MCP / Skill）
            →  结果写入目标（飞书文档 / 多维表格）  →  结果回传原频道
```

**异步性是核心产品判断**：任务下发后可以**关掉页面离开**，Agent 在后台继续跑，完成后回来验收。文章称之为"**离线任务**"。

## 作者的实操演示（跨境电商选品）

一条完整业务链路：

1. **取数**：通过阿里云百炼 MCP 广场里的「跨境选品 MCP」获取候选商品数据
2. **统一口径**：统一类目、价格、热度等字段
3. **落表**：按预设规则写入飞书多维表格的「选品机会池」
4. **二次分析**：对排名靠前的商品补充竞品价格、销量分布，生成"价格-评分-销量"气泡分析图
5. **分级**：高潜商品进入重点视图
6. **交付**：详细结论整理成飞书文档，并发回 Discord 频道
7. **持续更新**：文档、表格、Discord 任务围绕同一批商品持续更新，**团队不用重复搬运数据**

文章还演示了**定时任务**：把"每日 A 股盘前分析"设为每天 9:00 触发的 Schedule 任务，用一段 Prompt 定义，跑完通过飞书 CLI 推送。

## 可信数据源与 Skill 的作用

作者的论证（以金融分析为例，这一段比产品介绍本身更有价值）：

> 即便通过网页搜索整理黄金走势，**价格时间点、单位、时区和数据口径可能不一致**，每天早上 8 点自动生成晨报时，这些误差会直接进入结论。

所以他的配置逻辑是三段分工：

- **MCP**（金融类数据源）→ 提供可信的行情、利率、持仓数据
- **Skill** → 固定分析步骤、输出格式和**校验规则**
- **Agentic 框架** → 负责完成整项任务

并在输出侧做约束：**报告保留数据时间和来源，数据缺失时明确标记**。

## 与 OpenClaw 的对照（本知识库语境）

| 维度 | AgentConnect | [[OpenClaw（🦞 龙虾）]] |
|------|--------------|------------------------|
| Agent 数量 | **多角色**（每个角色独立模型/记忆/工作区/MCP/Skill/沙箱） | **单 Agent + 分层记忆**（L0–L3） |
| 记忆 | 角色级记忆 | **4 层记忆系统**是核心特色 |
| Harness | **可换**（Claude Code / Codex / DeepSeek Harness） | 自身即运行时 |
| 接入渠道 | Discord / Slack / Telegram / GitHub / GitLab | Telegram 等 |
| 共同点 | **IM 里 @Agent → 后台异步执行 → 结果回传** | 同 |

> 一句话对照：AgentConnect 把重点放在**"一个组织里有很多个专家 Agent 角色"的托管与编排**；OpenClaw 把重点放在**"单个 Agent 如何从交互中学习"的记忆分层**。

## 作者的核心判断

> **"会调用模型的团队越来越多，能让 Agent 真正接手固定任务的团队仍然很少，接下来的差距是怎么把这种「专家能力」丝滑的融合在日常业务流程中。"**

以及关于"沉淀为组织资产"的判断：Agent 进入企业执行链路后，**角色配置、Skill、数据连接、权限规则、跑顺的任务流程**都会沉淀为组织资产——所以自托管的价值在于**迁移时不用从零开始**。

## 上手建议（作者给的验证路径）

先选**一项每天重复、风险可控、容易验收的任务** → 接上可信数据源 → 规定输出到飞书文档或多维表格 → 看它能不能真正接进现有工作流程。
