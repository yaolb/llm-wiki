# OpenBot：把 Codex 与 Claude Code 组成协作团队

> 来源：AG雷达《已付费的编程 agent 组队上班了：OpenBot 把 Codex 和 Claude Code 变成协作团队》（2026-11-04）

## 一句话

**它不生产 agent，而是给「你已经在付费的编程 agent」加了一层本地工作台——让它们有名字、有工作区、有消息队列，能互相交接和审查。**

各家 CLI 与登录原样保留，OpenBot 在下面加一层调度。

## 核心机制

### 1. 每个 agent 是一个「队员」

- 有**名字**、**指令**（可用一句话自然语言生成，再人工修改）、**独立工作区**
- agent 之间可以**互发消息、交接任务、互相审查、传文件**

### 2. 派活即排队

- 消息可以连发，agent 忙时进入**队列**
- 支持**暂停、恢复、取消**

### 3. 换模型不换人

> 把 agent 从 Claude 换到 Codex，**工作区和对话都还在**。

- 额度用完、服务商过载或宕机时，可**自动切到另一家的备用模型**
- 切换会在聊天里**留下记录**（可追溯）

### 4. 数据分工

- 工作区、对话、文件、浏览器数据 → **存在本机**
- 发给模型的请求 → **仍会送到你选的服务商**（不是离线产品）

## 支持的服务商与运行时

- **Codex**（登 ChatGPT 账号）
- **Claude Code**（登 Claude 账号）
- **Gemini**（需 Google AI Pro 或 Ultra）
- **Grok**、**Cursor**、**Cline**
- **OpenCode**（有免账号的免费模型）
- 本地模型：**Ollama**、**LM Studio**
- 任何支持 **ACP 协议**的 agent（官方举例 Goose、Qwen Code）

## 上手四步

1. **安装**：openbot.run 或 GitHub Releases（macOS 13+ / Windows 10+ x64 / Linux AppImage）
2. **连接服务商**：登录已有账号；CLI 可由 OpenBot 托管下载并自动更新，也可用自己装的
3. **一句话建 agent**：如「一个负责每天整理 AI 新闻的研究员」，生成指令后检查修改
4. **派活**：发消息（可连发），看它在工作区产出文件；手机/网页可连回正在运行的实例

## 三个必须先知道的限制

**① 权限很大（开发预览阶段）**
官方 README 明确警告：agent 以**完全访问权限**运行——读写文件、执行命令、联网、控制内置浏览器**都不逐步确认**。
> 只派信得过的任务，做好备份。

**② 不是离线产品**
本机存的是工作区与对话，但**模型请求一定会发往对应服务商**，agent 打开的网页也走网络。

**③ 迭代极快**
10-30 到 11-03 五天内发了 v0.56 → v0.60 五个版本。功能与界面每周都在变，遇问题先看最新 changelog。

## 我的判断

**它真正解决的是两件事：**

1. **上下文孤岛**：Codex / Claude Code 各开一个终端，互相不知道对方存在，也不共享文件与状态
2. **额度孤岛**：一家限额用完就干等，而另一家可能还有额度

**价值在「工作区 + 队列」这一层，不在「多 agent 聊天」。**

> 聊天谁都会做；难的是**隔离**（每个 agent 有自己的文件系统视角）、**调度**（忙时排队、可暂停）、**可替换**（换模型不丢上下文）。

## 风险

- **许可**：商用要单独授权，不是拿来就能用
- **权限**：全权运行、不逐步确认，误操作代价高
- **依赖各家 CLI**：上游 CLI 一变，适配就断
- **模型切换的语义一致性**：不同模型对同一份指令理解不同，切换后产出风格会变（官方只保证「工作区和对话还在」，没保证「效果一致」）
- **单人产品**：⭐5,426、8 月建仓，团队规模与长期维护能力未知
