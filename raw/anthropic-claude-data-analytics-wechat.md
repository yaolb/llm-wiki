# AI 接管 95% 内部数据分析：Anthropic 如何把 Claude 调教成高级商业数据分析师

> 来源：微信公众号「AI寒武纪」（转载 Anthropic 官方博客）
> 原文：https://claude.com/blog/how-anthropic-enables-self-service-data-analytics-with-claude
> 链接：https://mp.weixin.qq.com/s/Y0DoUjK_eHdDNwLLDHcJTg
> 发布日期：2026-06-04（公众号转载）

## 核心结论

Anthropic 数据团队用 Claude 自动化了 **95% 的商业分析查询**，整体准确率约 **95%**。数据科学团队由此把精力转向因果建模、预测和机器学习。

**核心认知：数据分析不是写代码。** 写代码是开放的解题空间，创造性是加分项，文档和测试天然是防幻觉护栏；分析查询往往只有一个正确答案、来自一个正确的数据源，且没有任何确定性方式证明答案对。复杂性来自数据本身的模糊性——能否把用户问题准确映射到数据模型里具体、最新的字段。

## 三类主要失败模式

1. **概念与字段映射模糊**：几百到数百万候选字段，Agent 无法确定哪个最能回答用户问题（如"活跃用户"：什么算活跃？欺诈用户算不算？回溯窗口多长？）
2. **数据过期**：数据源、业务定义、表结构不断变化，Agent 知识过期，给出看似合理实则偏差的答案
3. **检索失败**：正确信息就在数据模型里、也有完整注释，但搜索空间太大，Agent 找不到

## 分层数据技术栈

| 层 | 对付的失败 | 做法 |
|---|---|---|
| **数据基础** | 映射模糊 | 权威数据集（少数受强治理的逻辑模型，废弃近似重复集）、执行标准（工具/CI/规定三重强制）、单一代码库（CI 保护跨层完整性）、元数据一等公民 |
| **可信数据源** | 映射模糊 | 四类按可信度排序：①语义层（编译好的指标/维度定义，强制优先）②数据血缘+转换依赖图 ③查询语料库（历史 SQL 直接给 Agent 收益 <1%，要提炼成结构化参考文档）④业务上下文（公司知识图谱：文档/路线图/决策记录/组织架构） |
| **Skill** | 检索失败 | Agent 的程序性知识：知识型路由器 Skill + 行动手册型 Skill（Unbook）+ 参考文档模板 + 成对创建 + 维护工程化（与模型同仓库、CI 钩子）+ 多界面一致（插件市场/云存储 Blob/MCP） |

## 验证体系（发现哪类失败还在泄漏）

### 离线评测
- 看板评测（Claude 自动生成+人工校验）+ 长尾评测（喂业务上下文让 Claude 生成合理问题）；业务方纠正回流为评测用例
- 固定基准值防漂移（快照日期/稳定事实表/评查询不评数字）；接入 CI
- 评测结果存数据仓库（Skill 版本/git SHA/模型 ID/断言结果/token/耗时）
- 按领域设上线门槛（最初约 90% 通过率才能宣布可用）；评测数量有边际收益递减（每主题几十个之后递减）

### 消融实验
- 每次只改一个变量，固定离线评测集比较通过率；负面结果也是结论（最有用的实验是负面的）
- **关键负面结果**：给 Agent 直接 grep 数千个看板/模型/Notebook SQL，准确率变化 <1%（信息在语料库里 80% 有，看了也用不上）→ 瓶颈在"结构"不在"访问"
- PR 粒度消融：改前改后对比写入 PR 描述；记录"没用清单"

### 在线验证
- 对抗性审查：Claude Skill 激进质疑答案假设 → 准确率 +6%，token +32%，延迟 +72%
- 来源标注页脚：数据层级/新鲜度/归属团队（"原始表，新鲜度未知"= 提醒先核实）
- 数据质量检查：被引用字段的最新性/完整性/异常
- 被动监控：语义层解决比例 + 纠正语言出现比例，汇入看板每周 Review
- 主动收集纠正案例：定时 Agent 扫描沟通渠道 → 起草参考文档一行修复 → PR + @领域负责人
- **未解决的静默失败**：答案错了但看起来合理、无人质疑直接用——缓解手段有页脚、高层内容人工确认、核心 KPI 每日与权威看板对比，但没有完善方案

## 从零开始

几个权威数据集 + 几十个离线评测用例 + 一个轻量知识型 Skill = 大部分收益。先对齐五个问题：今天 vs 未来的准确性、业务复杂度变化、受众技术水平、愿意花多少钱、访问权限/隐私底线。

## 附录：Skill File Skeleton（Anthropic 数据仓库 Skill 框架）

```markdown
---
name: [warehouse-skill]
version: [x.y.z]
description: "如果用户询问与[公司]数据仓库相关的任何[业务领域]问题，则调用此 Skill"
---

# [数据仓库] Skill 说明

## 描述
安全有效执行[数据仓库]查询的唯一权威来源。

## 执行查询
优先顺序：1. [托管连接] 2. [CLI 备用方案] 3. 均不可用 → 请用户认证并停止

# 语义层（必须的第一步）
受治理的语义层是每个数据问题的强制默认路径。
工作流：加载 → 发现（务必检查分群）→ 编译并运行 → 回退
> 不要过早放弃。不得以下列理由回退到原始 SQL

## 🏢 业务上下文
### 实体消歧义（必须澄清）
- "[术语A]"可能指：[...] — 必须澄清
### 业务术语 / 数据完整性要求 ⚠️
- 禁止编造数据/字段；区分观察结论与解读性结论

# 第2部分：操作方法
1. 查询前先澄清需求
2. 展示工作过程（过滤/包含排除/新鲜度）
3. 说清楚分母
4. 考虑样本偏差
5. 关联业务影响
6. 对抗性 SQL 审查（必须执行，不能自我认证）
7. 带来源信息汇报（来源/可信度/审查轮次/新鲜度/归属）

# 第3部分：数据参考资料
- 知识库导航：每个领域 → references/[domain].md（关键表/看板）
- 故障排查指南：信息缺失时怎么做、字段命名注意事项
```

**Skill 维护关键数据**：Skill Markdown 与转换模型同一代码库；改模型的 PR = 更新描述文档的 PR（约 90% 数据模型 PR 同一 diff 含 Skill 变更）；不维护的代价——上线 95% 离线准确率，一个月后跌到约 65%。
