> 关联：与 `entities/openclaw.md`（本机正在使用的 Agent 框架）**属于同一问题空间**——"在 IM 频道里 @Agent 下发后台任务、结果回传"；区别在于 AgentConnect 是**多 Agent 角色托管平台 + 可换 Harness**，OpenClaw 是**单 Agent + 记忆分层**

最近发现了一个比较有意思的开源项目，叫 AgentConnect。

它把 Claude Tag 所代表的 @Agent 去下发工作任务的方式，做成了一套可以自行部署的开源 Agent 托管平台。

我现在只要通过像 Discord 这样的 IM 频道中随时 @我的 Agent 军团就能够下发任务。

比如我要找擅长做电商经验分析的 Agent，去触发一项比如电商选品分析，调用外部数据，再把商品排行和结论写进飞书多维表格，制作成数据可视化分析看板。

同时这种 @Agent 的任务进入后台以后，我可以离开频道，等它完成后再回来查看结果，如果我要让擅长金融数据分析的 Agent，要让它继续帮我做一份关于实时的A股市场月度分析报告，也可以直接得到下面的结果报告。

实际上使用逻辑也蛮清楚的，我们可以先直接在 AgentConnect 上使用例如DeepSeek Harness 这样的框架去构建 不同岗位的 Agent。

让每个 Agent 专家各司其职，再给它配置引用数据源、工具和工作方法，最后规定任务从哪里进入、结果交到哪里，任务下发、后台执行和结果回传都由同一套平台承接。

这个就是 AgentConnect 的能力，平台开源并且采用了 Apache 2.0 协议，支持在在线页面去完成 Agent 的托管配置服务，企业可以把 Agent 的运行环境、凭证和业务数据留在自己的控制范围内。

01 
随时 @Agent 下发离线任务

Claude Tag 是 Anthropic 前段时间推出的一项与 Slack 这样的通信工具协作的能力。

作为用户只需要在不同的消息频道里 @Claude Tag，就可以下发任务。它本质上会读取当前对话的上下文，调用已经连接的工具，在后台完成任务，再回到原线程交付结果。

Anthropic 场景里面包括追踪产品指标、处理支持工单和排查 Bug，它传递了一个明确的产品判断：用户只需要完成一次 @，后面耗时更长的工作可以留给 Agent 在后台执行。

AgentConnect 沿着这条路径继续往前走，另外给用户提供了一个更灵活的可以自行选择 Agent Harness 框架，像Claude Code、Codex、DeepSeek Harness 这类框架可以直接一键创建成 Agent 。

除了 Agent 框架，AgentConnect 中的工具和运行环境也可以按需配置。

我们可以接入自有的联网服务器资源，作为 Agent 的执行基础设施，并在其中部署更多工具、数据源和专业能力。

当我们把 Agent 创建完成后，接入到不同的通信工具的方法也是非常简单。

我这次使用的是 Discord，直接点击 「Create Discord App」就可以跳转快速配置接入的流程，然后就可以直接在频道里面调用不同的 Agent了。

AgentConnect 也可以接入 Slack、Telegram、GitHub 和 GitLab，Webhook、代码仓库事件和定时计划同样可以触发任务。

如果想要让Agent专家更专业，可以选择为它添加可信的数据源，连接更多可操作的渠道，提供给它更多创造力工具，在这里我们可以直接添加自定义的 MCP 服务能力。

我这里是给 Agent 接上阿里云百炼 CLI 打通多模态模型的调用、另外配合阿里云百炼里面提供的MCP数据服务能力，接上飞书 CLI 直接可以操作文档知识库并进行协同分享。

只要能打开 Discord，就可以随时 @Agent 下发一项离线任务，后面的执行过程不需要一直盯着，我们只需要等待验收结果即可。

02 
一条选品任务要走完业务链路

刚刚咱们创建好 Agent ，并且我给上面的 Agent 配置了可信的跨境电商选品数据源的MCP，于是我就拿跨境电商选品场景做了一个演示，在 Discord 频道里发出一条选品数据分析任务的诉求。

我们只需要通过简单的询问就可以从离线任务中拿到对应的数据分析看板和表格。
我们可以从它运行的过程里面看到 Agent 思考和执行的所有过程。

可以看到先通过阿里云百炼 MCP 广场里的跨境选品 MCP 获取候选商品数据，统一类目、价格和热度等字段，按照预设规则再把结果写入飞书多维表格中的「选品机会池」。

接着，我让它对排名靠前的商品补充竞品价格、销量分布、价格评分销量的气泡分析图。

分析结果就可以继续写入同一张表，高潜商品进入重点视图，详细结论整理成飞书文档并发回 Discord 频道，文档、表格和 Discord 中的任务围绕同一批商品持续更新，团队协同就不用重复搬运数据了。

飞书 CLI 是我在当前环境中额外配置的集成能力，它让 Agent 可以编辑文档、操作多维表格、批量写入记录，再把结果送回 Discord，在 AgentConnect 这样使用就非常丝滑。

03 
一条任务背后 AgentConnect 做了什么

从 Discord 里的一次 @，到飞书多维表格里出现选品排行，中间经过了任务接收、Agent 执行、工具调用和结果写入。

AgentConnect 打包的，就是这一整段过程。

任务到达后，AgentConnect 会找到不同的 Agent 角色，每个角色可以单独选择执行框架、工作目录和权限，Claude Code、Codex、DeepSeek Harness 等 Agentic 框架都可以接入。

AgentConnect 里可以同时运行管理多个 Agent，我把这类角色用不同的业务场景进行划分。

每个角色都有自己的模型、记忆、工作区、MCP、Connectors、Skill 和沙箱服务。

比如选品 Agent 负责商品分析，金融 Agent 负责市场数据，内容 Agent 负责生成物料，咱们只需要在 Discord 里 @对应角色，就能把任务交给具备相应能力的 Agent。

Agent 开始执行以后，会根据任务调用已经配置好的 MCP 和 Skill。

我在电商选品 Agent 里面使用阿里云百炼 MCP 获取候选电商商品数据，再通过飞书 CLI 写入多维表格。

这样的类似流程也可以由定时计划来触发。

比如我们把每日的 A 股盘前分析可以作为一个定时任务，每天定时在早上9点触发，然后通过飞书CLI推送给我，我们只需要在AgentConnect 里去创建一个 Schedule 任务，然后通过一段简单的 Prompt 就可以实现下面的看板分析效果。

更绝的事情是，这种任务下发制的会话设计，让我们可以在下发后可以关闭页面，Agent 在后台继续运行。

一次 @ 由此变成了一项完整任务，一个完整的工作流可以由 Agent 的定时任务来承接长期使用，

04 
给每个 Agent 配上专业能力

AgentConnect 把任务链路接通以后，下一步是定义每个 Agent 具体能做什么。

前面也给大家提到了，作为 Agent 专家角色，提供必要的数据源、Skill 和模型服务，共同决定了一个角色的专业能力。

金融分析尤其明显，即便我们通过网页搜索整理黄金走势，价格时间点、单位、时区和数据口径可能不一致，每天早上 8 点自动生成晨报时，这些误差会直接进入结论。

所以我找了一些金融数据通过金融类 MCP 数据源获取，官方的可信数据源接入到 AgentConnect 会更有可信度。

这里使用阿里云百炼 CLI 在沙箱中完成 MCP 的配置和调用，把行情、利率、持仓等数据提供给金融 Agent，Skill 固定分析步骤、输出格式和校验规则，Agentic 框架负责完成整项任务。

配置完成以后，金融 Agent 按照固定方法调用金融类 MCP 获取数据源，报告保留数据时间和来源，数据缺失时也会明确标记。

同样的配置方式可以复制到法律检索、企业查询和内容创作等岗位，这都是一家企业会面临的专家Agent需求，然后结合 Skillhub 里面提供的很多专家 Skill 套件，这下专家团队就直接到位了。

海报 Agent 可以调用品牌 Skill 和图像模型，影视 Agent 可以使用分镜 Skill 和视频模型，每个角色只保留岗位需要的能力。

05 
开源让这些配置留在企业手里

我们其实可以预见到的是 Agent 会逐渐进入企业的执行链路，角色配置、Skill、数据连接、权限规则和已经跑顺的任务流程，都会沉淀为组织资产。

AgentConnect 提供了一条开源、自托管的路径，模型、Agentic 框架和消息渠道都可以更换，企业仍然保留岗位定义、运行记录和工具配置，迁移时不用从零开始。

如果你也想验证这件事，先选一项每天重复、风险可控、容易验收的任务，不如自己接上可信数据源，规定输出到飞书文档或多维表格，看看它能不能真正接进现有工作流程。

AgentConnect 已经开源，项目采用 Apache 2.0 协议并支持自托管，可以去查看部署方式，也可以顺手点一个 Star。

开源地址：https://github.com/agentconnect-md/agentconnect

我有一个越来越笃定的判断：会调用模型的团队越来越多，能让 Agent 真正接手固定任务的团队仍然很少，接下来的差距是怎么把这种「专家能力」丝滑的融合在日常业务流程中。

这也就是 AgentConnect 在做的事情了。

另外 AgentConnect 把这层能力开源了，咱们可以先让 Agent 跑通一个真实任务，然后在不同的组织内 @ 它。
