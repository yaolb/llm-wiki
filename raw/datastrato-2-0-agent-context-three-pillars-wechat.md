业务部门来问"这个月到底卖了多少钱"，你的数仓里有三张表、两套指标口径，还有一套是上周刚改的规则。过去这事靠数据团队吵一星期，现在把问题抛给了 Agent——但 Agent 更懵：数据它都找得到，可它不知道这三个数谁算的对、背后的业务规则是什么、自己能不能照着回答直接去下指令。

一个反直觉的现象正在发生：当 Agent 从"回答问题"走向"推理、决策与执行"，企业发现最大的瓶颈不再是模型会不会答，而是它没有可依赖的企业上下文。Agent 不仅要知道"数据在哪里"，还要知道"数据意味着什么""业务实体如何关联""行动受哪些规则约束"。把这三件事组织成可信、可复用、能持续更新的上下文，正在成为企业 AI 基础设施的核心命题。

Datastrato 创始人兼 CEO 堵俊平的解法，是把 Agent 的上下文拆成三重支柱，逐层递进：第一层统一元数据，用 Apache Gravitino 跨云、跨引擎、多模态地把数据资产描述清楚，解决 Agent"不知道数据在哪、哪些能用"；第二层开放语义层，让指标、维度、业务定义跨工具共享，把"一个指标多个口径"的语义孤岛钉死，让不同工具和 Agent 拿到一致的业务理解；第三层 Ontology，把业务实体、关系与规则显式建模，让 Agent 能把自然语言里的业务意图，精确映射到真实数据和操作边界内——先统一元数据，再开放语义，最后 Ontology 收口，三层衔接，Agent 才能在明确治理边界里把"懂业务"变成"可执行的动作"。

更关键的是对"上下文怎么建"的路径纠偏。堵俊平指出，自上而下从应用任务出发建语义，会快速出价值，但也容易形成重复建模、彼此复用的上下文孤岛；自下而上从元数据治理出发，底座扎实，却没法只凭技术结构推导出业务含义。更可持续的是混合路径：以业务场景牵引建模，用统一元数据连接业务概念、数据资产与治理规则，再靠业务校验和 Agent 使用反馈持续迭代——因为上下文会"过期"，数据漂移、业务规则变化、模型升级都会让旧上下文失效，不保鲜的上下文反而会把 Agent 带偏。

10月23-24日，DACon 2026 北京站，Datastrato 创始人兼 CEO 堵俊平将在主论坛带来演讲，分享开放语义、Ontology 与元数据：Agent Context 的三重支柱，并首发 Datastrato 2.0（Gravitino 2.0 企业版）——融合三重支柱、推动数据目录向 AI Context Platform 演进的产品化实践。

堵俊平，Datastrato 创始人兼 CEO，Apache Gravitino 项目发起人，原 LF AI & Data 基金会董事主席，Apache 软件基金会成员，数据与开源领域专家。曾任全球 500 强企业开源业务总经理、腾讯开源负责人兼大数据研发总监、Cloudera Hadoop 团队负责人。

Datastrato 的另一位讲师李明皇在本届大会分享 Agent 如何"每个回答都有据可查"——堵俊平这次讲的是更靠前的一步：Agent 开口之前，喂给它的上下文底座该怎么建。

听完整场演讲，你能带走三件可复用的东西。

一套"统一元数据→开放语义层→Ontology"三层递进的 Agent 上下文认知框架，知道企业上下文该从哪层开始搭、每层解决什么问题。

一套自上而下与自下而上两条路径的对比方法，以及"业务场景牵引建模 + 统一元数据连接 + 反馈迭代"的混合建法，避免每建一个应用就重搭一遍语义、留下孤岛。

一份数据目录向 AI Context Platform 演进的产品化架构参考与技术选型思路，包括怎么用开源项目（如 Apache Gravitino）先把跨云跨引擎的元数据底座立起来。
